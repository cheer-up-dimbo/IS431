5.3.5 Dashboard & Analytics

Beyond the core intelligence systems, BoxBunny provides a comprehensive software layer that transforms raw training data into actionable insights, delivers AI-powered coaching analysis, and enables convenient remote control — all designed to make the training experience as seamless as possible.

5.3.5.1 Communication Architecture

The system uses a 3-layer communication architecture connecting the desktop GUI, phone dashboard, and ROS 2 backend:

  • GUI ↔ ROS Core: A GuiBridge running as a background QThread in the PySide6 application, subscribing to 10+ ROS topics and emitting Qt signals for thread-safe UI updates. Three async service clients handle session start/stop and LLM generation.
  • Dashboard ↔ GUI: IPC files in /tmp/ with 100ms polling — the phone dashboard writes JSON command files that the GUI reads and executes, enabling remote control without direct network coupling.
  • Dashboard Frontend ↔ Backend: Standard REST API calls for data operations, plus WebSocket for real-time session updates during active training.

The phone dashboard is accessible over the robot's WiFi access point, meaning users can control BoxBunny from their phone while standing at the robot. It was specifically designed for convenience: no typing on the 7-inch touchscreen with boxing gloves on, no bending down to interact with a small display, and natural mobile interaction for chatting with the AI coach.

5.3.5.2 Analytics & Performance Insights

All training data flows through the system and is aggregated into meaningful insights for the user:

Session-Level Analytics: After each training session, a SessionPunchSummary with 20+ fields is published, capturing punch distribution by type, force distribution across light/medium/hard, pad distribution, rounds completed, punches per minute, maximum power, and movement metrics (depth range and lateral displacement). This data is stored in the per-user SQLite database for long-term tracking.

Trend Analysis: The phone dashboard provides time-series analytics across four selectable periods (7 days, 30 days, 90 days, all time) for five key metrics: training volume (total punches), reaction time, punch power, defence rate, and stamina. Users can track their improvement over time and identify areas that need work.

Peer Comparison: Population benchmarks compare the user's performance against demographic norms segmented by age group, gender, and skill level across 6 metrics. Percentile tiers range from "Getting Started" (below 10th percentile) through "Average", "Above Average", "Advanced", to "Elite" (above 90th percentile).

Personal Records: All-time bests for power, stamina, and reaction time are automatically tracked in a dedicated personal_records table and surfaced on the dashboard with the date achieved.

Sparring-Specific: Defence breakdown showing blocks, slips, dodges, and hits received. The weakness profile reveals which punch types the user struggles to defend against — the same data that drives the AI sparring engine's targeting behaviour.

5.3.5.3 AI Coach Analysis & Training Suggestions

Post-Session Analysis: After each session, the LLM receives the full SessionPunchSummary as context and generates a 2-3 paragraph analysis referencing specific metrics — punch count, power trends, weak areas, and improvement compared to previous sessions.

Actionable Drill Suggestions: The LLM can output structured tags in the format [DRILL:Name|combo=1-2|rounds=2|work=60s|speed=Medium]. The phone dashboard parses these into clickable action cards that can launch the suggested training configuration directly on the robot with one tap.

Interactive AI Chat: A full-screen chat interface with word-by-word streaming (20ms per word) lets users ask technique questions, request custom training plans, get explanations of their statistics, or have a general conversation about boxing. Conversation history is persisted and follow-up suggestions are provided after each response.

Convenience Design: The phone dashboard means users chat with the AI coach from their phone instead of typing on a 7-inch touchscreen — much more natural, especially with boxing gloves on. This design was directly motivated by user feedback during the CDE AI Fair, where touchscreen typing was identified as a friction point.

5.3.5.4 Phone Dashboard Features

The phone dashboard is a Vue 3 Single Page Application (Composition API, Pinia state management, Tailwind CSS, Chart.js) served by a FastAPI backend. Key views include:

  • Dashboard Home: XP progress ring towards next rank, weekly training goal with streak counter, training heat map (activity by day of week), quick stats with trend arrows showing week-over-week change, peer comparison percentile bars, recent session summary card, and an AI coach quote of the day.
  • Performance: Trend charts across selectable time periods for all 5 key metrics with personal best callouts.
  • Training Remote: Quick preset grid for one-tap session start, navigation buttons to remotely control the GUI on the touchscreen from the phone, and a press-and-hold height adjustment control. Users can configure their entire training session from their phone and walk to the robot ready to go.
  • Coach View (coach accounts only): Dashboard for group circuit training — manage participant rotation, view live stats per participant, load training presets, and review past coaching sessions.

5.3.5.5 API & Database Design

FastAPI Backend (7 routers under /api/)

Router Key Endpoints Purpose
auth login, signup, pattern-login, profile JWT auth (7-day TTL) + SHA-256 pattern lock
sessions current, history, trends, detail, raw Session data with pagination and mode filtering
gamification profile, achievements, leaderboard, benchmarks XP, ranks, badges, peer comparison
chat status, message, history LLM coaching via ROS service bridge
remote command, height, presets GUI remote control via IPC files
presets list, create, update, delete, favourite Training preset management
coach load-config, start/end-station, live, sessions Group training management (coach role)

Two-Tier SQLite Database

Main DB (boxbunny_main.db): shared tables for users (with password hash and pattern lock), auth sessions, training presets, and coaching sessions.

Per-User DB (users/{username}/boxbunny.db): isolated tables for training sessions, session events, combo progress, performance test results (power, stamina, reaction), sparring sessions, weakness profiles, gamification (XP, achievements, streaks, personal records).

Design rationale: Per-user databases provide complete data isolation, enable concurrent writes without lock contention, and simplify per-user backup and data export.

WebSocket

Real-time session updates via ws://<host>:8080/ws, supporting events for session started/stats/completed, with 30-second keepalive ping/pong and automatic reconnection using exponential backoff (max 10 attempts) with state sync on reconnect.

5.3.5.6 Gamification System

6 Rank Tiers

XP Calculation

Base XP varies by mode (Training 50, Sparring 80, Free 30, Performance Tests 40), with bonuses for session completion and score performance. Difficulty multipliers scale from 1.0× (Beginner) through 1.3× (Intermediate) and 1.6× (Advanced) to 2.0× (Elite). Minimum 10 XP per session.

12+ Achievements

Including "First Blood" (first session), "Century" (100 punches), "Speed Demon" (lightning reaction time), "Weekly Warrior" (7-day streak), and "Perfect Round" (100% accuracy). Duplicate unlock prevention ensures each badge is awarded only once.

Streaks & Goals

Daily training streak tracking with longest streak records. Configurable weekly training goal (default 3 sessions/week) with progress tracking.
