5.3 Robot Intelligence (Yogeeswaran)

The Robot Intelligence subsystem delivers real-time boxing action recognition and adaptive robot behaviour. At its core is a computer vision pipeline that classifies 8 punch types using depth-based 3D voxel motion features fused with 2D pose estimation. Reaction time detection and human tracking build on processed frames from this action prediction pipeline.

A ROS 2 workspace orchestrates these CV outputs alongside IMU sensing, AI sparring logic, and local LLM coaching to fulfil three product needs: Performance Analytics, Adaptive Fight Intelligence, and Realistic Training Partner.

Requirements and Design Considerations

These requirements were derived from the Function Analysis, user journey, and the physical constraints of deploying real-time computer vision on an embedded platform during live boxing training.

ID Requirement Rationale
RI-1 Classify 8 boxing actions in real-time at >=30 FPS Match human defensive reaction speed; voxel temporal features depend on consistent 30fps frame intervals
RI-2 End-to-end latency (camera to motor command) <=150ms Matches average intermediate boxer defensive reaction time
RI-3 Classification accuracy >=90% on unseen person validation set Reduce false triggers and incorrect counter-punches during live sparring
RI-4 CV + IMU sensor fusion for confirmed punch events Single-source detection unreliable; fusion eliminates false positives from camera noise and accidental pad contacts
RI-5 All inference on-device (NVIDIA Jetson Orin Nano), no cloud Gym WiFi unreliable; latency budget prohibits cloud round-trip; zero internet requirement
RI-6 Multiple adaptive AI sparring styles with weakness tracking Prevent user habituation; support varied training objectives
RI-7 Real-time coaching feedback via local LLM Personalized technique guidance without cloud dependency

System Architecture

The system runs on an NVIDIA Jetson Orin NX, hosting 12 ROS 2 Humble nodes that communicate via 21 custom message types and 6 services.

The primary data flow follows four stages:

  • Capture — Intel RealSense D435i streams depth + RGB frames
  • Perception — cv_node runs YOLO pose estimation and 3D voxel extraction in parallel, feeding a transformer-based action classifier
  • Fusion — punch_processor matches CV detections with IMU pad impacts using temporal and pad-constraint filtering
  • Downstream — Confirmed punches propagate to session_manager, drill_manager, sparring_engine, analytics_node, and llm_node

Session State Machine

The session lifecycle is managed by a 5-state machine. Each state transition triggers coordinated side effects across all nodes — for example, the CV frame rate scales from ~6 fps (idle) to 30 fps (active), and data collection only runs during active rounds. The default cycle is 3 rounds of 180s work + 60s rest, with all training modes (techniques, sparring, free, performance tests) sharing this same state machine.
