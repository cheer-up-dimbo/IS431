5.3 Robot Intelligence (Yogeeswaran)

The Robot Intelligence subsystem encompasses two tightly integrated components: (1) a real-time boxing action recognition model that classifies 8 punch types using depth-based 3D voxel motion features fused with 2D pose estimation, and (2) a ROS 2 system workspace that orchestrates computer vision inference, IMU sensing, AI coaching via a local LLM, and adaptive sparring behaviour. Together, these deliver the product needs of Performance Analytics, Adaptive Fight Intelligence, and Realistic Training Partner — mapping to three core functions: Reaction Time (system responsiveness), Human Tracking (accurate motion following), and Counter-Punching (safe, reactive sparring without a partner).

5.3.1 Requirements and Design Considerations

The following requirements were derived from the Function Analysis, user journey, and the physical constraints of deploying real-time computer vision on an embedded platform during live boxing training.

ID Requirement Rationale
RI-1 Classify 8 boxing actions in real-time at >=30 FPS Match human defensive reaction speed; voxel temporal features depend on consistent 30fps frame intervals
RI-2 End-to-end latency (camera to motor command) <=150ms Matches average intermediate boxer defensive reaction time
RI-3 Classification accuracy >=90% on unseen person validation set Reduce false triggers and incorrect counter-punches during live sparring
RI-4 CV + IMU sensor fusion for confirmed punch events Single-source detection unreliable; fusion eliminates false positives from camera noise and accidental pad contacts
RI-5 All inference on-device (NVIDIA Jetson Orin Nano), no cloud Gym WiFi unreliable; latency budget prohibits cloud round-trip; zero internet requirement
RI-6 Multiple adaptive AI sparring styles with weakness tracking Prevent user habituation; support varied training objectives
RI-7 Real-time coaching feedback via local LLM Personalized technique guidance without cloud dependency

5.3.2 System Architecture

The system runs on an NVIDIA Jetson Orin NX with 8 GB shared LPDDR5 memory, hosting 12 ROS 2 Humble nodes that communicate via 21 custom message types and 6 services. The primary data flow begins at the Intel RealSense D435i depth camera, where the cv_node performs YOLO pose estimation and 3D voxel extraction in parallel threads, feeding a transformer-based action classifier. Predictions flow to the punch_processor node, which fuses CV detections with IMU pad impacts using temporal matching and pad-constraint filtering to produce confirmed punch events. These confirmed punches propagate to downstream nodes: session_manager (session lifecycle), drill_manager (50 combo drills), sparring_engine (5 AI opponent styles), analytics_node (real-time statistics), and llm_node (local AI coach). A 5-state session machine (IDLE → COUNTDOWN → ACTIVE → REST → COMPLETE) coordinates per-state side effects across all nodes — the CV frame rate adapts between 30 fps during active training and ~6 fps when idle, the IMU switches between navigation and training modes, and data collection activates only during active rounds.

All system parameters are managed through YAML configuration files (boxbunny.yaml, ros_topics.yaml, drills.yaml, sparring.yaml) with topic names loaded at startup via constants.py, ensuring no magic numbers in code.
