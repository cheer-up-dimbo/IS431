Testing and Evaluation

This section presents the functional testing conducted during development, user testing observations from the public showcase event, and the limitations that remain.

Functional Testing

Functional testing was conducted on the features available at the time of the "Robotics Meets AI Showcase" event in late January 2025. The features tested were the combo curriculum system, the reaction time test, and the navigation stack. Test scenarios verified correct behaviour under normal use conditions.

All functional tests passed. The navigation stack test is worth highlighting: the scenario traced a five-page deep navigation path and verified that pressing back four times returned through each page in the correct reverse order, confirming that the centralised stack handled arbitrary navigation depth correctly.

User Testing: Robotics Meets AI Showcase

Members of the public physically interacted with BoxBunny at the "Robotics Meets AI Showcase" event in late January 2025, specifically within the Robotics and AI in Work and Play segment. Two displays were available during the demonstration: the original 7-inch touchscreen mounted directly on the robot, and a larger external monitor connected to the same Jetson Nano showing the same GUI output.

During the session, participants and observers consistently gravitated toward the larger monitor when reading training results and navigating between pages. Users who attempted to operate the 7-inch screen during active training reported difficulty reading combo prompts and statistics. Several participants noted that the text was too small to follow comfortably while also focusing on technique. Users who switched to the larger monitor did not report the same issues.

These observations validated a hardware revision. The 7-inch display was replaced with a 10.1-inch IPS capacitive touchscreen (1280x800 resolution, DSI interface). The upgrade improved text legibility and made the analytics pages easier to read during and after training. Because the GUI used proportional layout sizing rather than fixed pixel coordinates, the existing interface scaled to the new resolution without requiring a redesign cycle.

Limitations

Computer Vision Integration

The computer vision subsystem communicates with the GUI through a file-based handshake rather than a direct API call. This was a consequence of the CV and GUI subsystems being developed in parallel without a stable shared interface being finalised before the submission deadline. The mechanism works reliably but introduces unnecessary file I/O overhead that a direct function call would avoid.

AI Coaching Availability

The AI coaching feature falls back to hardcoded template responses when the language model is unavailable. On the Jetson Nano's 4 GB RAM, loading the Qwen 2.5 3B model alongside the GUI and other subsystems is not always feasible. The fallback provides functional feedback, but it limits the personalisation of coaching on memory-constrained hardware.

Display Upgrade Validation

The display upgrade to 10.1 inches occurred late in the project. While the interface scaled correctly to the new resolution, there was no opportunity to conduct a second round of structured user testing on the new hardware. The improvement in readability is based on qualitative observation during the event rather than controlled measurement.
