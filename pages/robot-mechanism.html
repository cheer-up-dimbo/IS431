5.2 Robot Mechanism

The robot mechanism encompasses all physical hardware — mechanical structures, actuators, sensors, and supporting electrical and firmware systems — that together enable BoxBunny to behave as a realistic, interactive boxing training partner rather than a static target. At the system level, the mechanism has five principal responsibilities:

  1. Stable and safe base — resist punching-induced overturning moments, protect the user's footwork space, and remain portable for transport and public demonstrations.
  2. Rotation about the yaw axis — re-angle the robot to present changing attack and defence lines during drills, replicating a coach's pivoting footwork.
  3. Height adjustability — match the robot's head and torso targets to users of different statures so that striking zones remain anatomically correct.
  4. Impact-absorbing contact surfaces — provide realistic, safe striking targets with embedded sensing for training analytics.
  5. Arm actuation — deliver targeted punches at anatomically correct striking zones using a high-velocity 2-DOF mechanism, enabling jabs, hooks, and uppercuts.

These functions were decomposed from the broader project goals established in the problem clarification and design methodology phases. A key integration principle across all subsystems is that the mechanism was designed from system-level behaviour downward, rather than by combining isolated parts. The robot first had to remain upright, safe, and spatially compact in a boxing environment. Only after these high-level requirements were defined were they decomposed into subsystem-level functions following the left side of the V-model.

Overall Subsystem Architecture

Mechanical Stack

The mechanism is organised as a vertical stack, ordered from the ground up. This ordering principle ensures that the heaviest and most load-critical components sit closest to the base, where they can best resist overturning moments:

  1. Trapezoidal Base — welded steel platform providing stability and portability
  2. Slewing-Ring Yaw Stage — low-profile rotation module at the base of the stack
  3. Ball-Screw Linear Slide — forward–backward translation above the yaw stage, expanding the reachable target footprint
  4. Telescopic Height-Adjustment Column — motorised screw-jack column with structural guiding
  5. Upper Body — torso, head, and 2-DOF coaxial striking arms with multi-layer padding

The linear motion axis (ball-screw-driven sliding table on dual linear rails) sits above the rotation stage. This configuration was chosen because it significantly increases the reachable footprint of target positions for the same base size, compared to placing rotation above linear motion. All translational and rotational footwork axes are fully motorised for programmable, repeatable training sequences, while height adjustment uses a self-locking screw jack for safety.

Electrical & Control Architecture

The robot mechanism employs a distributed control architecture where parallel processing coordinates vision inference, sensor feedback, and motor control in real time. The system adopts a layered approach:

  • ROS 2 provides the modular, message-based framework for higher-level perception, decision making, and user-interface components running on the Jetson compute module.
  • micro-ROS / FreeRTOS provides lightweight, deterministic task scheduling on microcontrollers (Teensy 4.0) for low-latency motor control and sensor acquisition loops.

A closed-loop PID cascade controller ensures smooth, safe motion under dynamic boxing loads. The cascade implements three nested loops — position (outermost), velocity, and current (innermost) — each operating at progressively higher update rates to match the response speed of the physical variable it controls. This structure enables the mechanism to:

  • Damp sudden impacts (user punches) and restore position smoothly
  • Limit torque when the user grabs or holds an arm
  • Prevent overcurrent and motor burnout during stall conditions
  • Compensate load spikes gradually without aggressive corrections

Individual subsystem pages detail their specific electrical interfaces, power budgets, communication buses, and low-level control strategies.

System Integration Test Plan

Beyond individual subsystem verification, the robot mechanism must be tested as an integrated system — all five subsystems operating together under realistic training conditions (without Robot Intelligence). The system-level integration tests validate cross- subsystem interactions that cannot be caught by isolated subsystem tests:

Test Description Acceptance Criterion
Coordinated Motion Height adjustment + yaw rotation simultaneously under operator control No mechanical binding, smooth motion, no loss of position
Loaded Sparring Strike delivery while user is actively punching the padding Arm maintains strike accuracy; IMU correctly detects user punches during robot strikes
Power Budget Measure total system current draw under worst-case concurrent actuator load Total draw within PSU capacity with ≥ 20% headroom
Communication Reliability Run CAN + I²C buses concurrently at full rate for 30 min continuous sparring Zero bus hangs; ≤ 0.1% packet loss
Safety E-Stop Trigger emergency stop during active strike motion All motors decelerate to zero within 100 ms; no uncontrolled motion
