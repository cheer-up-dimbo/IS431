5.2.2 Rotation — Electrical & Control

V-Model Traceability: This page addresses RM-4 (yaw angular velocity ≥ 150°/s) and RM-1 (hold commanded angle under punch impact) at the electrical and control layer.

Requirements Cascade

The rotation electrical subsystem responds to the following system-level requirements defined in the Robot Mechanism section:

System Req Subsystem Implication
RM-4 Yaw angular velocity ≥ 150°/s — motor and drive ratio must deliver sufficient speed under load
RM-1 Hold commanded angle under punch impact — closed-loop position control with disturbance rejection

Motor Specification

The base rotation uses a Z55BLD400-24GU 400 W BLDC motor with a 25:1 planetary gearbox, controlled via the ZBLD C20-800LRC CAN motor driver. The motor provides high torque at low speed — ideal for the timing-belt-driven yaw stage, which requires smooth re-angling under the inertia of the full upper structure.

Parameter Value
Motor model Z55BLD400-24GU (400 W BLDC)
Gearbox 25:1 planetary
Driver ZBLD C20-800LRC (CAN interface)
Nominal voltage 24 V
Peak current draw ~16 A (stall)
Position feedback AS5047P 14-bit magnetic encoder (SPI)

Control Architecture

The base rotation controller is an Arduino Uno R4 WiFi, operating as a separate controller from the Teensy 4.0 that manages the arm motors. Communication with the Jetson host uses WiFi UDP rather than a physical cable.

Signal Flow

Jetson Orin NX                    Arduino Uno R4 WiFi
   V4 GUI  ─── WiFi (UDP) ───►  UDP listener
                                      │
                                 CAN (125 kbps)
                                      │
                                 Z55BLD400 Motor
                                      │
                                 AS5047P Encoder (SPI)

Design Rationale

  1. CAN baud mismatch: The Z55BLD400 driver operates at 125 kbps; the Damiao arm motors use 1 Mbps. Placing both on the same CAN bus would require firmware complexity for dual-baud switching. Separate buses eliminate this entirely.
  2. Wireless eliminates cable fatigue: A USB cable routed through the rotating base joint would experience continuous twist/flex and eventually fail. WiFi UDP removes this failure mode.
  3. Independent failure domain: Base rotation is decoupled from arm control; either can fail without affecting the other. The Arduino can be power-cycled without disturbing the Teensy or the Damiao motor CAN bus.
  4. Already validated: Encoder + CAN motor code was validated on the Arduino R4 during isolated bench testing before integration.

Power Integration

The Z55BLD400 motor is connected to the 24V motor bus via the distribution busbar, alongside the arm motors and height motor. The Arduino controller is powered from the isolated 12V logic rail through a LM2596-based 12V→5V buck converter (≥1 A), ensuring motor bus OVP events do not reset the base rotation controller.

Component Rail Current Notes
Arduino R4 WiFi 5V (from 12V buck) ~300 mA WiFi active + logic
WCMCU-1051 CAN transceiver 5V ~50 mA From Arduino 5V rail
AS5047P encoder 3.3V ~15 mA From Arduino 3.3V regulator
Total from PSU 5V ~400 mA 2 W nominal
Wire routing: Power cable (2-wire, 5V + GND) from the buck converter to the Arduino should route along the rotation axis to minimise twist. A slip ring is recommended for continuous rotation >±2 turns; if software limits base rotation to ±360°, a flexible cable with strain relief is sufficient. Connector: JST-XH 2-pin (field-removable, polarised, rated ≥2 A). RegenClamp Required: The Z55BLD400 is a 400 W BLDC motor with a 25:1 gearbox — back-EMF during rapid deceleration will spike the 24V bus, potentially triggering the same OVP failure documented for the height motor. A third RegenClamp V0.3 unit should be installed between the busbar and the ZBLD driver.
