4. Final Design (Jeanette and Zakir)

With requirements and methodology established in Chapters 2 and 3, this chapter consolidates them into a system architecture (4.1) and user journey (4.2). These define the top-level structure and interaction model that inform the subsystem-level conceptual design in Chapter 5.

4.1 System Overview (Jeanette)

Building on the identified product needs, the BoxBunny robot is organised into three key subsystems, each addressing a distinct set of functions:

  • User Interface: touchscreen, visual feedback, and control logic for configuring and running training sessions.
  • Robot Mechanism: the integrated physical platform comprising Base (stability and portability), Rotation (yaw tracking), Height Adjustment (user-adaptive positioning), Padding (impact sensing and contact points), and Arm Actuation (punch execution via 2-DOF coaxial differential joints). Together these subsystems position the robot and deliver safe, realistic striking interaction.
  • Robot Intelligence: primarily User Tracking, enabling the robot to respond to the boxer's movement and adapt drills in real time.

For a detailed mapping of how each product need (Table 4) relates to these subsystems, see Appendix 5: Product Needs to Subsystem Mapping.

4.2 User Journey (Zakir)

The swim lane diagram below shows how the three subsystems collaborate across the five phases of a training session. During setup, only the User Interface is active. At countdown, all three subsystems initialise: the intelligence layer ramps CV inference to 30 Hz and resets tracking baselines, while the mechanism auto-adjusts height using person detection. During active training, the subsystems operate in a continuous loop where intelligence detects and classifies user actions, the mechanism responds with arm actuation and yaw tracking, and the interface displays live feedback and coaching tips.
